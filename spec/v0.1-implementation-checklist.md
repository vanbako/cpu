## Purpose

This checklist turns the frozen v0.1 architecture contract into implementation work packages for a semantic simulator, assembler/disassembler, firmware path, kernel bring-up path, debugger, verification suite, and first RTL or cycle-level model.

It is a handoff document. The owning specification stories remain normative.

## Readiness Decision

Implementation can begin now for:

- Architectural state and semantic simulator execution.
- Capability representation, tags, permissions, and faults.
- CSR/CCSR architectural behavior.
- Cell-addressed memory and tag storage.
- Instruction semantics using internal instruction enums.
- Trap, interrupt, debug, and single-step state transitions.
- ABI conformance tests and software contract tests.
- Memory composition, LL/SC, fence, TLB, cache, and DMA litmus tests at the architectural level.

Implementation should wait for one additional binding document before treating these as stable external interfaces:

- Final binary opcode bit assignments.
- Concrete platform profile for reset vector, memory map, interrupt-controller interface, secondary start mechanism, fatal-entry handling, and debug transport.
- Byte-oriented object-file or binary-container serialization of 24-bit cells.
- OS trap-frame, context-switch, and language ABI supplements.

The recommended first implementation track is a semantic simulator with an internal decoded-instruction representation. That avoids blocking on final opcode allocation while still validating the architecture.

## First Runnable Milestone

The first milestone should be a single-core semantic simulator running hand-authored decoded programs.

Minimum scope:

1. Implement cell-addressed memory with 24-bit cells and capability-slot tags.
2. Implement architectural register state for `D0-D15`, `C0-C7`, special capabilities, scalar CSRs, and CCSR indices.
3. Implement capability checks, derivation, tag propagation, and fault reporting.
4. Implement fetch placement and hidden slot behavior without depending on final binary opcodes.
5. Implement enough instructions for straight-line integer, capability, load/store, branch, call, trap, and return tests.
6. Implement direct trap entry, `IRET`, non-monitor debug halt, and precise exception packets.
7. Run E15-S01/E15-S02 automated checks plus story-derived simulator tests.

Exit criteria:

- A decoded program can reset into ROM-like state, execute simple integer/capability code, take a trap, and return with `IRET`.
- Capability tags cannot be created through integer dataflow.
- Faulting instructions leave destination and memory state unchanged according to the owner stories.
- Slot-1 instruction faults and returns are observable through `EPCC.slot`.

## Cross-cutting Invariants

Every implementation track must preserve these invariants:

| Invariant | Required check |
| --- | --- |
| Cell addressing | No architectural byte address is accepted internally except at external serialization boundaries. |
| Capability tag integrity | Integer registers, scalar CSRs, ordinary payload bits, and byte containers cannot create valid tags. |
| Payload/tag atomicity | `CLC`, `CSC`, coherence transfer, cache maintenance, debug access, and protected return-stack operations move payload and tag together. |
| Monotonic authority | Capability derivation can narrow or preserve authority but never widen it. |
| Precise retire | Faulting or debug-stopped instructions expose either pre-instruction state or full post-retire state, never partial state. |
| One hardware saved level | Trap, interrupt, and debug-monitor entry overwrite one `EPCC`/reporting level; software owns deeper frames. |
| Slot correctness | Explicit control transfers enter slot 0; only legal fall-through or slot-aware restore reaches slot 1. |
| Reservation clearing | E08-S02 reservation-clear events are implemented even when the instruction's normal effects do not update reservation state. |
| Store/tag visibility | Integer stores clear overlapped capability-slot tags at the same visibility point as payload writes. |
| No hidden platform behavior | Platform-defined or implementation-defined choices are documented before portable software depends on them. |

## Subsystem Checklist

### Architectural State

Required:

- Model `D0-D15` as writable 48-bit integer registers.
- Model `C0-C7` as 96-bit payload plus tag.
- Model `PCC`, `DSC`, `RSC`, `DDC`, `EPCC`, `TVC`, `KSC`, and `KRC` as special capabilities.
- Carry hidden slot state in `PCC` and `EPCC`.
- Keep `SR.SLOT` as a mirror of `PCC.slot`.
- Implement per-core state for all mandatory fast CSRs.
- Keep scalar CSR numbers distinct from CCSR indices.

Tests:

- Reset state matches E11-S01 and E11-S02.
- `CCSRRD`/`CCSRWR` copy payload and tag exactly.
- `CCSRWR PCC` and `CCSRWR EPCC` set the hidden slot to 0.
- `EPCCRD`/`EPCCWR` preserve payload, tag, and slot for trap frames.

### Memory and Tags

Required:

- Represent memory as 24-bit cells.
- Represent one tag per naturally aligned 4-cell capability slot.
- Implement 48-bit integer objects as 2 aligned cells.
- Implement capability objects as 4 aligned cells plus tag.
- Reject unaligned `LD48`/`ST48`, `LL48`/`SC48`, `CLC`/`CSC`, and capability-slot accesses.
- Clear capability-slot tags on integer stores that overlap the slot.
- Prevent ordinary accesses to protected return-stack storage.

Tests:

- `ST48` to either half of a capability slot clears that slot tag.
- `LD48` over capability payload bits returns only integer data.
- `CLC` from an untagged slot returns an invalid-tag capability without fault.
- `CSC` storing a valid local capability requires `SL`.
- Ordinary `LD48`, `ST48`, `CLC`, and `CSC` over protected return-stack storage fault without side effects.

### Capability Semantics

Required:

- Implement `CMOVE`, `CGETADDR`, `CSETADDR`, `CINCADDR`, `CSETBOUNDS`, `CANDPERM`, `CSEAL`, and `CUNSEAL`.
- Implement `OTYPE_ENTRY` and `OTYPE_RETURN` restrictions.
- For every capability fault, populate `CAPCAUSE`, `FAULTCAPIDX`, and `TVAL` according to the selected owner story.
- For every non-capability fault, clear capability reporting to `NONE` on trap entry.

Tests:

- Invalid tags cannot authorize any dereference, derivation, seal, unseal, fetch, or CCSR-mediated authority creation.
- `CSEAL` can create entry capabilities when authorized.
- Ordinary `CSEAL` cannot create return capabilities.
- Ordinary `CUNSEAL` cannot unseal entry or return capabilities.

### Instruction Semantics

Required:

- Start with an internal decoded-instruction enum using canonical mnemonics.
- Implement instruction placement independent of final binary encodings.
- Implement integer, memory, capability, control-transfer, CSR, CCSR, atomic, fence, cache-maintenance, debug-adjacent, `WFI`, and `PAUSE` semantics according to owner stories.
- Treat `SYS` as canonical and `SCALL` as a source-level synonym once assembly exists.
- Exclude `CAS48`, `CAS96`, and generic `AMO*` from the mandatory baseline.

Tests:

- Every mandatory mnemonic in `tools/software_contract_matrix.md` has at least one semantic test.
- Every privileged instruction has user-mode privilege-fault tests.
- Every faulting instruction leaves normal destination and memory effects unchanged.
- `BRK` follows ordinary trap behavior unless `DEBUGCTL.BRKHALT=1`.

### Trap, Interrupt, and Debug Priority

Required:

- Implement the selected-event model from `tools/fault_priority_matrix.md`.
- Implement direct synchronous trap entry through `TVC`.
- Implement maskable interrupt eligibility and vector selection.
- Implement fatal entry failure rather than recursive normal trap delivery when `TVC` or vector state is invalid.
- Implement non-monitor debug halt, debug-monitor entry, hardware breakpoint/watchpoint events, and single-step completion.
- Suppress comparators in `DEBUG_HALTED` and debug-monitor execution.

Tests:

- Fetch faults beat instruction breakpoints.
- Effective-access faults beat data watchpoints.
- Watchpoints beat memory/register effects after access checks succeed.
- Single-step reports after normal retire and before same-boundary ordinary interrupts.
- Non-monitor debug halt preserves `EPCC`; debug-monitor entry consumes the one hardware saved level.

### ABI and Software Contract

Required:

- Treat ABI preservation as a software convention, not hardware protection.
- Implement public call-boundary expectations for `D0-D5`, `D0-D1`, `D12-D15`, `C0-C3`, `C0`, and `C6-C7`.
- Implement mixed overflow argument layout for ABI tests.
- Preserve capability tags for capability arguments, returns, spills, and callee-saved registers when software uses the required operations.
- Keep syscall register conventions platform-overridable but baseline-compatible.

Tests:

- Integer and capability argument/return placement matches `tools/software_contract_matrix.md`.
- Capability spills use `CSC`/`CLC` and preserve tags.
- Integer stores are rejected as capability spills.
- Tail-call tests restore callee-saved state and public stack alignment.

### Reset, Startup, and Platform Binding

Required before portable firmware:

- Define `RESET_VECTOR`.
- Define ROM, RAM, device, and protected return-stack regions.
- Define initial tag state for ROM/RAM capability tables if any.
- Define platform interrupt-controller CSR or MMIO bindings.
- Define secondary-core start mailbox location, ownership, ordering, and signal mechanism.
- Define fatal trap-entry and interrupt-entry escalation behavior.
- Define debug transport and authentication policy.

Simulator can start before these are final by using a documented test platform profile.

Tests:

- Only core 0 starts executing after cold reset.
- Secondary cores remain `STOPPED` or `WFI_PARKED` until startup.
- Valid mailbox plus ordering plus start event reaches `STARTED`.
- Invalid mailbox authority fails startup without partial state installation.
- Start signal to an already `STARTED` core does not replace live state.

### MMU, TLB, Cache, Ordering, and DMA

Required:

- Implement `SATP`, `ASID`, `RADIX4` translation, PTE format, and page permissions.
- Implement private ITLB and DTLB behavior with local invalidation forms.
- Implement page memory types and access legality.
- Implement TSO-like ordering for normal coherent CPU memory.
- Implement `LL48`/`SC48` reservations and progress assumptions.
- Implement `FENCE`, `FENCE.I`, and `SFENCE.VM` ordering effects.
- Model L1/L2 payload/tag movement and coherence for architectural tests.
- Model noncoherent, tag-unaware DMA ownership sequences for litmus tests.

Tests:

- Run scenarios from `tools/memory_consistency_litmus.md`.
- Page permission and capability permission are both required.
- `SC48` access faults trap rather than reporting reservation failure.
- Faulting `LL48` clears any previous reservation and creates none.
- Synchronous trap entry clears active reservations according to E08-S02.
- DMA overwrite of capability slots clears backing-memory tags.

### Counters and Observability

Required:

- Implement `CYCLE`, `INSTRET`, `DEBUGCTL`, `PERFSEL`, and `PMC0-PMC7` behavior.
- Stop mandatory counters and PMCs in `DEBUG_HALTED`.
- Count debug-monitor instructions as ordinary kernel execution after entry.
- Implement `PERFSEL` unsupported-event `WARL` discovery.

Tests:

- `INSTRET` increments for normally retired instructions only.
- `BRK`, `SYS`, `SCALL`, trap entry, interrupt entry, and debug entry do not increment `INSTRET`.
- Explicit kernel writes to `INSTRET` do not also apply an implicit increment for that instruction.
- Unsupported performance events read back as `EVENT=NONE`, `EN=0`.

## Definition of Ready for RTL

RTL or cycle-level implementation should not start from prose alone. It is ready when:

- The semantic simulator has passing tests for core instruction semantics, traps, slots, capabilities, and memory tags.
- The fault-priority and memory litmus suites exist as executable tests or machine-readable scenarios.
- A final opcode allocation exists for decoder work.
- A minimal platform profile exists for reset, interrupts, and debug/fatal behavior.
- The pipeline implementation chooses explicit commit points for every multi-effect instruction.
- The cache/MMU model has explicit tag movement, TLB invalidation, and fault packet interfaces.

Prototype RTL exploration can begin earlier, but it should be treated as disposable until these gates are met.
