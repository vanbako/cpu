## Decision

CPU v0.1 defines `LL48` and `SC48` as the mandatory aligned 48-bit load-linked/store-conditional primitives.

They operate on 48-bit integer memory objects, which are exactly two 24-bit cells and require 2-cell alignment.

`LL48` is an atomic 48-bit load with the side effect of installing a per-core reservation.

`SC48` is a conditional 48-bit integer store. It succeeds only when the current core still holds a matching reservation and the implementation chooses not to fail spuriously. Success stores the source integer value and returns `0`. Failure performs no memory store and returns `1`.

## Instruction Forms

| Instruction | Assembly form | Source registers | Destination registers | Summary |
| --- | --- | --- | --- | --- |
| `LL48` | `LL48 Dd, Ca, Di` | `Ca`, `Di` | `Dd` | Load two cells through `Ca + Di` and install a reservation. |
| `SC48` | `SC48 Dr, Ds, Ca, Di` | `Ds`, `Ca`, `Di` | `Dr` | Conditionally store `Ds` through `Ca + Di` and report success or failure. |

`Ca` is the memory-authorizing capability register. `Di` is a signed 48-bit cell offset. `Ds` is the 48-bit integer value to store. `Dd` receives the loaded 48-bit value. `Dr` receives the `SC48` result code.

Opcode bit assignments and compact encodings are owned by E04-S06.

All source operands are read before any destination register is written. If `Dr == Ds` or `Dr == Di`, `SC48` uses the pre-instruction source value and then writes the result code to `Dr`.

## Effective Address

Both instructions compute the target word address the same way:

```text
effective = Ca.cursor + signed(Di[47:0])
word      = [effective, effective + 2)
```

The calculation is performed in mathematical integers, not modulo `2^48`. The effective address is a cell address.

The target word must satisfy:

- `0 <= effective <= 2^48 - 2`
- `effective mod 2 = 0`
- The entire two-cell word is within `Ca` bounds.

Misaligned access raises `ALIGN_FAULT`.

## Access Checks

`LL48` performs the same authority checks as an integer load:

1. `Ca.tag` must be valid.
2. `Ca` must be unsealed.
3. The effective address calculation must not overflow or underflow the 48-bit cell address space.
4. The effective address must be 2-cell aligned.
5. The entire two-cell word must be within `Ca` bounds.
6. `Ca` must have `LD`.
7. Translation, privilege, page permission, and memory-type checks must allow an atomic load from the target word.

`SC48` performs the same authority checks as an integer store before testing the reservation:

1. `Ca.tag` must be valid.
2. `Ca` must be unsealed.
3. The effective address calculation must not overflow or underflow the 48-bit cell address space.
4. The effective address must be 2-cell aligned.
5. The entire two-cell word must be within `Ca` bounds.
6. `Ca` must have `ST`.
7. Translation, privilege, page permission, and memory-type checks must allow an atomic store to the target word.

Access checks are performed even if no matching reservation exists. A failed access check raises a trap; it does not return an `SC48` failure code.

The complete combined priority between capability, translation, privilege, alignment, and memory-type faults is finalized by E09-S07. This story preserves the E07-S02 baseline priority: instruction-defined capability-source checks occur before effective-access translation and memory-type faults.

## Reservation State

Each core has at most one architecturally relevant LL/SC reservation.

A successful `LL48`:

- Atomically loads the target 48-bit word.
- Replaces any previous reservation held by the current core.
- Records the target aligned word and an implementation reservation granule containing that word.

A faulting `LL48`:

- Leaves `Dd` unchanged.
- Does not create a new reservation.
- Does not perform a memory load.

Reservation state is private to one core. It is not visible to software except through later `SC48` success or failure.

## Reservation Granule

The reservation granule is implementation-defined within these v0.1 limits:

- It must contain the target aligned 48-bit word.
- It must be at least the target word.
- It may be as large as the containing cache line.
- It must not exceed the containing cache line.

With the v0.1 16-cell cache line, the largest legal reservation granule is the 16-cell line containing `effective`.

Portable software must assume that stores by other cores anywhere in the containing cache line may cause `SC48` failure. Software may rely only on the guarantee that a store to the exact target word can conflict with the reservation.

An implementation must document whether it tracks word, sub-line, or cache-line reservations.

## Store-conditional Success

After all `SC48` access checks pass, `SC48` succeeds only if all of these are true:

1. The current core has a valid reservation from a previous successful `LL48`.
2. The `SC48` target aligned word is the same aligned word reserved by that `LL48`.
3. The reservation has not been cleared by a conflicting event.
4. The implementation does not choose a spurious failure for this instruction.

On success:

```text
memory_payload[effective, effective + 2) = Ds[47:0]
Dr = 0
```

The memory store is one atomic 48-bit store in the E08-S03 memory model. It is ordered as a store and becomes globally visible through the CPU coherence point according to the TSO-like rules.

A successful `SC48` is an ordinary integer-data store for capability-integrity purposes. If either written cell overlaps a naturally aligned 4-cell capability slot, the tag for that slot is cleared, exactly like `ST48`.

`SC48` success consumes the current core's reservation.

## Store-conditional Failure

`SC48` fails without trapping when access checks pass but the reservation test does not produce success.

Failure cases include:

- No active reservation exists on the current core.
- The active reservation was created by a different target aligned word.
- The active reservation was cleared by a conflicting event.
- The implementation chooses a spurious failure.

On failure:

```text
Dr = 1
```

No memory payload is written. No capability tag is cleared or modified. Failed `SC48` has no global store visibility point.

`SC48` failure consumes the current core's reservation.

Result codes:

| `Dr` value | Meaning |
| ---: | --- |
| `0` | Store succeeded. |
| `1` | Store failed; no memory update occurred. |

All other result values are reserved. A v0.1 implementation must not produce them.

## Spurious Failure

`SC48` may fail spuriously after all access checks pass.

Spurious failure is architecturally indistinguishable from another non-trapping `SC48` failure:

- `Dr = 1`
- Memory payload unchanged.
- Memory tags unchanged.
- No global store visibility point.
- The reservation is consumed.

Spurious failure is allowed so implementations can handle internal conflicts, replacement, pipeline replay, or conservative coherence events without exposing microarchitectural details.

The bounded-retry progress guarantee is owned by E08-S02. E08-S01 only permits spurious failure; it does not permit an implementation to violate the later progress rule.

## Faults Versus Failures

`SC48` has two different unsuccessful outcomes:

| Outcome | Trap? | `Dr` written? | Memory changed? | Typical reason |
| --- | --- | --- | --- | --- |
| Fault | Yes | No | No | Invalid capability, sealed authority, bounds, alignment, permission, translation, privilege, or memory-type rejection. |
| Failure | No | Yes, `1` | No | Missing, cleared, mismatched, or spuriously rejected reservation. |

Faulting `LL48` or `SC48` leaves destination registers and memory unchanged.

For `SC48`, access faults take precedence over reservation failure. Software cannot use `SC48` failure as a permission or translation probe.

## Capability and Tag Interaction

`LL48` loads only the two payload cells as integer data. It never returns a capability tag and cannot create a valid capability in an integer register.

Successful `SC48` writes only integer payload cells. It cannot write a capability tag. Its overlap with capability memory is handled by tag clearing:

- If the written word is `[A, A + 2)` and overlaps capability slot `[S, S + 4)`, the tag for slot `S` is cleared.
- Because `SC48` requires 2-cell alignment, it can overlap at most one naturally aligned capability slot.
- A failed or faulting `SC48` does not clear tags.

This keeps `SC48` consistent with `ST48` and prevents LL/SC loops from forging valid capabilities through integer data writes.

## Coherence Interaction

`LL48` and `SC48` participate in the same normal coherent cache hierarchy as `LD48` and `ST48`.

Minimum coherence requirements:

- `LL48` obtains a coherent readable copy of the target line.
- Successful `SC48` requires store authority and exclusive ownership before its store becomes globally visible.
- Failed `SC48` does not publish a coherent store or change payload or tags.
- Payload and any required tag clear from a successful `SC48` become visible at one coherent visibility point.

E08-S02 owns the complete list of reservation-clear events, including same-core stores, other-core stores, coherence invalidations, evictions, interrupts, and context switches.

## Memory Type Limits

LL/SC synchronization is guaranteed only for normal coherent cacheable memory.

For v0.1, executing `LL48` or `SC48` on a memory type that does not participate in CPU coherence raises `ACCESS_FAULT`, unless a later platform profile explicitly defines stronger behavior.

This excludes device memory and noncoherent DMA buffers from portable LL/SC lock algorithms.

## Examples

Basic atomic increment:

```text
retry:
    LL48  D0, C1, D2      ; D0 = *addr, reserve addr
    ADDU  D3, D0, D4      ; D4 = 1
    SC48  D5, D3, C1, D2  ; if success, *addr = D3 and D5 = 0
    TST   D5
    Bcc.NE retry
```

If another core stores to the reservation granule between `LL48` and `SC48`, the `SC48` may return `1` and must not update memory.

## Verification Notes

Minimum conformance checks for later assembler, simulator, and RTL work:

- `LL48` loads a 48-bit word from an even cell address.
- `LL48` rejects odd cell addresses with `ALIGN_FAULT`.
- `LL48` requires valid unsealed load authority with `LD`.
- A successful `LL48` replaces any prior reservation on the same core.
- `SC48` rejects odd cell addresses with `ALIGN_FAULT`.
- `SC48` requires valid unsealed store authority with `ST`, even when no reservation exists.
- `SC48` to the same aligned word as the active reservation can succeed and returns `0`.
- Successful `SC48` stores exactly two cells.
- Successful `SC48` clears any overlapped capability-slot tag.
- `SC48` without an active reservation returns `1` and leaves memory unchanged.
- `SC48` to a different aligned word than the active reservation returns `1` and leaves memory unchanged.
- Failed `SC48` does not clear capability tags.
- Spurious `SC48` failure returns `1` and leaves memory unchanged.
- `SC48` on noncoherent or device memory raises `ACCESS_FAULT`.
